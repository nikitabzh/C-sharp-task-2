# Задание 2. Вариант 1: Иерархия осветительных приборов

## Общий обзор
В проекте реализовано WPF-приложение на C# с архитектурой MVVM. Цель — создать систему управления разными типами осветительных приборов с использованием наследования и полиморфизма.

## Архитектура
- `Models/` содержит модельную иерархию:
  - `LightingDevice` — абстрактный базовый класс.
  - `Lantern`, `DeskLamp`, `FloorLamp`, `Chandelier` — конкретные реализации.
  - `IPluggable` — интерфейс для приборов, требующих подключения к сети.
- `ViewModels/MainViewModel.cs` управляет списком приборов и командами UI.
- `Commands/RelayCommand.cs` реализует поведение команд (модель команд).
- `MainWindow.xaml` и `MainWindow.xaml.cs` связывают UI с ViewModel через DataContext.

## Основная функциональность
- Базовый класс `LightingDevice` поддерживает состояние `IsOn`, `IsBroken`, методы включения/выключения и событие поломки (`Broken`).
- При поломке прибор автоматически переходит в состояние выключен.
- Для включения проверяется состояние сети и отсутствие поломки, если прибор реализует `IPluggable`.

## Поведение наследников
- `Lantern` и `DeskLamp`: одна лампа, простая логика переключения, повышенная устойчивость к поломке.
- `FloorLamp`: аналогично `DeskLamp`, но с учётом специфики (может быть запасный механизм переключения).
- `Chandelier`: режимная модель, переключается между 3 состояниями и реализует цикличное включение/выключение.

## UI и управление
- Основное окно отображает список устройств с полями:
  - `Name`.
  - `IsOn`.
  - `IsBroken`.
  - `IsPlugged` (для `IPluggable`).
  - Текущее состояние люстры.
- Команды для UI:
  - `TurnOnCommand`, `TurnOffCommand`, `TogglePlugCommand`, `BreakCommand`.
- Поведение кнопок привязано к выбранному устройству через ViewModel.

## Входные данные и инициализация
- Список устройств формируется при старте приложения (конструктор ViewModel), без жесткой привязки к данным в моделях.
- Конструкторы устройств не содержат жестких значений: состояние задаётся извне для тестируемости.

## Проверка соответствия требованиям
- Использована структура MVVM, отдельные папки `Models`, `ViewModels`, `Commands`.
- Абстрактный класс + полиморфизм + интерфейсы реализованы.
- Событие поломки работает и влияет на состояние устройства.
- Имеются специфические механики включения для логически разных приборов.

## Вывод
Проект выполнен как учебная работа по шаблону MVVM. Реализован набор классически различающихся осветительных устройств. В UI отображается состояние каждого прибора и доступные действия, а логика управления сосредоточена во ViewModel и модели.
